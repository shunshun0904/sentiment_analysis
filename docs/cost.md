# 料金と、過去データの扱い

## 結論

**過去分の削除は、料金のためには要りません。** 貯まるのは1年で約10MB、
料金にすると月0.04円ぶんです。10年放置しても100MB弱、月0.4円。

ただし「1年で365ファイル、10年で3,650ファイル」は見通しが悪いので、
別の理由で畳んでいます ── 詳細は下の「畳む方針」。

## 内訳(東京リージョン / 5分間隔 = 月8,640回の実行)

| 項目 | 量 | 月額(概算) |
|---|---|---|
| S3 PUT | 3回/実行 × 8,640 + 日次1回 ≒ 26,000回 | **約18円** |
| S3 GET(Lambda側) | 4回/実行 ≒ 35,000回 | 約2円 |
| S3 GET(閲覧者) | 1人が1時間見て12回。1日1,000回でも月3万回 | 約1円 |
| S3 ストレージ | 1年ぶん貯めて約10MB | 0.04円 |
| Lambda | 512MB × 10秒 × 8,640回 = 43,200 GB秒 | **0円**(無料枠40万GB秒/月の1割) |
| EventBridge スケジュール | 8,640回 | 0円 |
| CloudWatch Logs | 数十MB(14日で削除) | 0円(無料枠5GB/月) |
| SSM Parameter Store(標準) | 8,640回の取得 | 0円 |
| **合計** | | **月20〜25円** |

*1ドル150円換算。単価は AWS の公開価格(S3標準: ストレージ $0.025/GB・月、
PUT $0.0047/1,000回、GET $0.00037/1,000回)から計算した概算です。
実際の請求は AWS の料金ページと Cost Explorer で確認してください。*

**料金の主役はストレージではなくPUTリクエスト**です。つまり、
過去データを消しても月額はほとんど変わりません。効くのは更新間隔のほうで、
5分→15分にすれば PUT が1/3になり、月18円→6円になります。

## 唯一まとまった額になりうるもの

フェーズ2(`SCORER=claude`)の Anthropic API 利用料、月150〜300円の想定です。
これはS3とは桁が違うので、次の2つで蓋をしてあります。

- 新着記事しかLLMに投げない(スコア済みのIDは `state/articles.json` に記録)
- `CLAUDE_MAX_ARTICLES`(既定120)で1実行あたりの上限を固定

それでも、**AWS Budgets で月1ドルの通知**は設定しておくことを勧めます
(手順は `docs/aws-setup.md`)。想定外の増え方に気づく唯一の仕掛けです。

## 畳む方針

料金ではなく、扱いやすさのために2段階にしてあります。

| 置き場 | 粒度 | 保持 | なぜ |
|---|---|---|---|
| `data/{INDEX}/history/YYYY-MM-DD.json` | 5分刻み(288点/日) | **400日**(自動削除) | 直近の細かい動きを見るため |
| `data/{INDEX}/daily.json` | 1日1点(始値/終値/平均/最小/最大) | **消さない** | 長期の推移。10年で約300KB |
| `state/{INDEX}/articles.json` | スコア済み記事 | **7日**(自動削除) | 消えても次の実行で取り直すだけ |

Lambda は毎回、前日ぶんの履歴を `daily.json` に1点として畳みます
(`_rollup_previous_day`)。**畳んだあとで生の履歴が消えても、長い目盛りの推移は残ります。**

保持日数を変えたいときは、デプロイ時のパラメータ1つです。

```bash
sam deploy --parameter-overrides HistoryRetentionDays=90
```

削除はS3のライフサイクルルールがやるので、こちらで消す作業はありません。

## 増えたときに効く順

もし将来コストが気になったら、効く順は次のとおりです。

1. **更新間隔を延ばす**(5分→15分で PUT が1/3。相場の温度は15分刻みでも十分読める)
2. 市場が閉じている時間帯の実行を止める(EventBridge の cron を平日日中だけに)
3. `HistoryRetentionDays` を短くする ← **効果はいちばん小さい**(月0.04円の話)
