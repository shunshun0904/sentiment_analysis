# 料金と、過去データの扱い

## 結論

**過去分の削除は、料金のためには要りません。** 全部で月2〜4円です。
記事の監査ログを1年ぶん貯めても月0.6円、集計済みの系列は10年で15MB(月0.06円)。

60分間隔にしたことで、v1(5分間隔)の想定より1桁小さくなりました。

## 内訳(東京リージョン / 60分間隔 = 22回/日 = 月660回の実行)

| 項目 | 量 | 月額(概算) |
|---|---|---|
| S3 PUT | 6回/実行 × 660 ≒ 4,000回 | **約2.8円** |
| S3 GET(Lambda側) | 8回/実行 ≒ 5,300回 | 約0.3円 |
| S3 GET(閲覧者) | 1人が1日見て24回。1日1,000回でも月3万回 | 約1.7円 |
| S3 ストレージ | 記事ログ400日ぶんで約160MB + 系列 | 約0.7円 |
| Lambda | 512MB × 10秒 × 660回 = 3,300 GB秒 | **0円**(無料枠40万GB秒/月の1%未満) |
| EventBridge スケジュール | 660回 | 0円 |
| CloudWatch Logs | 数MB(14日で削除) | 0円(無料枠5GB/月) |
| SSM Parameter Store(標準) | 660回の取得 | 0円 |
| Alpha Vantage | 22 req/日(無料枠25) | **0円** |
| **合計** | | **月2〜4円** |

*1ドル150円換算。単価は AWS の公開価格(S3標準: ストレージ $0.025/GB・月、
PUT $0.0047/1,000回、GET $0.00037/1,000回)から計算した概算です。
実際の請求は AWS の料金ページと Cost Explorer で確認してください。*

**閲覧者のGETが最大の項目になりうる**点だけ注意してください。
`latest.json` は 60〜100KB あるので、見る人が増えると転送量が効きます
(S3 の下り転送は月100GBまで無料。1回100KBなら100万回ぶん)。

## 貯まり方

| 置き場 | 1日あたり | 保持 | なぜ |
|---|---|---|---|
| `history/articles/YYYY-MM-DD.jsonl` | 約400KB(2,000件 × 約200B) | **400日**(自動削除) | 集計の再現・検証用 |
| `history/sentiment.jsonl` | 約4KB(22点 × 約180B) | **消さない** | 長期の推移。10年で約15MB |
| `public/latest.json` | 上書き。60〜100KB | — | 画面が読むもの |
| `state/` | 数十KB。上書き | **7日**(自動削除) | 消えても次の実行で作り直せる |
| `observe/sources.json` | 数KB。上書き | — | ホワイトリスト確定用 |

集計済みの系列と記事ログは **prefix が違う**ので、
ライフサイクルで記事が消えても長期の推移は残ります。

保持日数を変えたいときは、デプロイ時のパラメータ1つです。

```bash
sam deploy --parameter-overrides ArticleRetentionDays=90
```

削除はS3のライフサイクルルールがやるので、こちらで消す作業はありません。

## 既知の限界: `sentiment.jsonl` の read-modify-write

S3 に追記APIは無いので、`append_jsonl` は毎回**全部読んで全部書き直して**います
(毎時1回・単一ライターなので競合はしません)。

`history/sentiment.jsonl` は年1.4MBずつ増えるため、**5年で7MB**、
そのころには毎実行で7MBの読み書きが22回/日発生します。料金にすると誤差ですが、
Lambda の実行時間には効きます(数百ミリ秒の増加)。

気になる規模になったら、キーを年ごとに割る(`history/sentiment-2026.jsonl`)のが
いちばん簡単です。`store.append_jsonl` の呼び出し側だけの変更で済みます。
記事ログは既に日ごとに割ってあるので問題ありません。

## 唯一まとまった額になりうるもの

**いまの構成にはありません。** Alpha Vantage のセンチメントスコアは無料で、
記事数が増えてもコストが増えないのが、このソースを選んだ決定的な理由です。

将来 LLM で自前スコア化する案は**不採用**にしてあります。実測で記事流量が
1時間で206件(=1日数千件)と判明し、Haiku 4.5 でも月$20〜30規模になるためです。

それでも、**AWS Budgets で月1ドルの通知**は設定しておくことを勧めます
(手順は `docs/aws-setup.md`)。想定外の増え方に気づく唯一の仕掛けです。

## 増えたときに効く順

1. **閲覧者向けの転送を減らす** — `latest.json` の `window` が容量の大半です。
   `config.PUBLIC_WINDOW_ARTICLES` を下げるか、5分刻みの再構成を Lambda 側に移す
   (`docs/SCHEMA.md` の代案)
2. **更新間隔を延ばす** — 60分→120分で PUT が半分。ただしクォータ側には余裕があるので、
   料金のために延ばす意味はほぼありません
3. `ArticleRetentionDays` を短くする ← **効果はいちばん小さい**(月0.7円の話)
